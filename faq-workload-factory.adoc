== 개요 및 비용

.Workload Factory란 무엇이며 비용은 얼마입니까?
Workload Factory는 데이터베이스, VMware 마이그레이션, EDA 프로젝트 등 FSx for ONTAP 파일 시스템에서 실행되는 워크로드를 최적화하기 위한 수명 주기 관리 플랫폼입니다. Workload Factory 자체는 무료로 사용할 수 있습니다. FSx for ONTAP 파일 시스템, VMware Cloud on AWS 인프라, 기타 AWS 서비스 등 배포하는 서비스에 대해 AWS에 비용을 지불합니다.

link:workload-factory-overview.html["Workload Factory에 대해 알아보십시오"].

.Workload Factory는 어떤 AWS 리전에서 사용할 수 있습니까?
Workload Factory는 FSx for ONTAP이 지원되는 모든 상용 지역에서 작동하지만, 중국 지역, Secret Cloud 또는 Top Secret Cloud에서는 작동하지 않습니다.

https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/["지원되는 AWS 리전을 확인하세요."^]

== 계정 및 로그인

.Workload Factory 콘솔과 NetApp Console의 차이점은 무엇입니까?
두 콘솔 모두 Workload Factory에 액세스할 수 있는 웹 기반 콘솔입니다. NetApp Console은 FSx for ONTAP 파일 시스템과 워크로드를 다른 데이터 서비스와 함께 한 곳에서 관리할 수 있는 하이브리드 환경을 제공합니다. Workload Factory 콘솔은 FSx for ONTAP에서 실행되는 워크로드에 중점을 둔 전용 환경입니다.

link:console-experiences.html["어떤 콘솔을 사용할지 결정하세요"].

.어떻게 가입하나요? 그리고 첫 계정을 만들면 어떤 일이 발생하나요?
NetApp 지원 사이트(NSS) 자격 증명으로 가입하거나 NetApp 클라우드 로그인을 생성하십시오. 클라우드 로그인의 경우 로그인하기 전에 이메일 주소를 인증해야 합니다. 처음 로그인할 때 리소스, 워크로드 및 자격 증명을 구성하는 계정을 생성하게 되며, 모든 Workload Factory 기능에 액세스할 수 있는 계정 관리자가 됩니다. 이미 NetApp Console을 사용하고 있다면 Workload Factory에서 NetApp 계정을 사용하므로 이미 계정에 속해 있는 것입니다.

link:sign-up-and-log-in.html["회원가입 후 로그인하세요"].

.제 계정을 AWS GovCloud (US) 계정으로 설정해야 할까요? 나중에 변경할 수 있나요?
자격 증명과 암호가 GovCloud에 유지되며 GovCloud (US) 엔드포인트 및 리전만 사용하는 계정이 필요한 경우 GovCloud (US) 옵션을 선택하십시오. 이 선택은 영구적입니다. GovCloud 계정은 자격 증명을 추가하고 링크를 수동으로 생성해야 합니다.

.Workload Factory 계정에 다른 사용자를 초대하려면 어떻게 해야 하나요?
NetApp Console에서만 계정을 관리할 수 있습니다. 계정 관리자는 그곳에서 멤버를 추가하고, 초대받은 사용자는 가입 방법에 대한 안내 이메일을 받게 됩니다.

link:sign-up-and-log-in.html["다른 사용자를 계정으로 초대하십시오"].

== 자격 증명 및 권한

.Workload Factory를 사용하려면 AWS 자격 증명을 추가해야 하나요?
자격 증명 추가는 시작 단계에서 선택 사항이므로 AWS 계정에 액세스하지 않고도 Workload Factory를 사용할 수 있습니다. 그러나 FSx for ONTAP 파일 시스템을 생성 및 관리하고 데이터베이스 등 워크로드를 배포 및 관리하려면 Workload Factory에 자격 증명이 필요합니다.

* link:quick-start.html["Workload Factory 시작하기"].
* link:add-credentials.html["자격 증명 추가"].


.Workload Factory 자격 증명은 어떻게 작동하나요?
자격 증명은 AWS 역할 수임 흐름을 사용합니다. 각 자격 증명 세트는 사용자가 선택한 워크로드 기능 및 권한 수준에 따라 하나 이상의 IAM 정책과 Workload Factory가 수임하는 IAM 역할로 구성됩니다. 나중에 언제든지 기능을 더 추가할 수 있습니다.

link:add-credentials.html["자격 증명 추가"].

.자격 증명을 수동으로 추가해야 할까요, 아니면 CloudFormation을 사용하여 추가해야 할까요?
수동 방식을 사용하면 Codebox에서 정책 JSON을 복사하여 AWS Management Console에서 IAM 정책과 IAM 역할을 생성합니다. 자동 방식을 사용하면 기능을 선택하고 CloudFormation 스택이 IAM 정책과 IAM 역할을 자동으로 생성합니다. GovCloud (US) 자격 증명은 CloudFormation이 지원되지 않으므로 수동으로 추가해야 합니다.

link:add-credentials.html["자격 증명 추가"].

.어떤 권한 수준을 선택할 수 있으며, 어떤 권한을 부여할지 어떻게 결정합니까?
권한 정책은 워크로드별로 묶입니다. 스토리지의 경우 *보기, 계획 및 분석*, *운영 및 복구*, *파일 시스템 생성 및 삭제* 중에서 선택할 수 있습니다. 데이터베이스 워크로드의 경우 *보기, 계획 및 분석*, *운영 및 복구*, *데이터베이스 호스트 생성* 중에서 선택할 수 있습니다. 이러한 정책을 통해 IT 정책에 따라 단계적으로 신뢰도를 할당할 수 있습니다. 현재 사용할 기능만 선택하십시오.

link:permissions-reference.html["권한 참조"].

.자동 권한 확인 기능은 어떤 역할을 하며, 계속 활성화 상태로 유지해야 할까요?
*자동 권한 확인 사용*을 선택하면 권한 정책에  `iam:SimulatePrincipalPolicy`이(가) 추가되어 Workload Factory가 작업을 완료하기 전에 필요한 AWS 권한이 있는지 확인할 수 있습니다. 자격 증명을 추가한 후에는 이를 제거할 수 있지만, 유지하는 것이 좋습니다. 이는 부분적으로 성공한 작업에 대한 리소스 생성을 방지하고 수동 리소스 정리 작업을 덜어줍니다.

link:add-credentials.html["자격 증명을 추가할 때 자동 권한 확인을 활성화하십시오"].

.더 이상 필요하지 않은 자격 증명을 삭제할 수 있습니까?
FSx for ONTAP 파일 시스템과 연결되지 않은 자격 증명만 삭제할 수 있습니다. Workload Factory 콘솔에서 *제거*를 사용하거나 NetApp Console에서 *삭제*를 사용하십시오.

link:manage-credentials.html["자격 증명을 제거합니다"].

== 링크

.링크란 무엇이며, 저에게 필요한가요?
링크는 Workload Factory 계정과 하나 이상의 FSx for ONTAP 파일 시스템 간의 신뢰 관계 및 연결을 생성합니다. 링크는 AWS Lambda를 사용하므로 Amazon FSx for ONTAP API에서 제공하지 않는 기능을 ONTAP REST API 호출을 통해 모니터링하고 관리할 수 있습니다. 시작하는 데 링크가 필요하지는 않지만, Workload Factory의 모든 기능을 사용하려면 링크가 필요합니다.

link:links-overview.html["링크에 대해 자세히 알아보세요"].

.어떤 기능에 링크가 필요합니까?
링크가 필요한 기능은 다음과 같습니다.

* FSx for ONTAP의 잘 설계된 상태
* ONTAP EMS 이벤트 모니터링
* AI 기반 자율형 랜섬웨어 보호(ARP/AI)
* 볼륨 및 스토리지 VM 복제
* SMB/CIFS 공유 및 NFS 내보내기 정책
* iSCSI 볼륨 관리
* 스냅샷 정책
* 볼륨 자동 확장 및 inode 관리
* 클론 생성
* 추가 ONTAP 지표 및 LIF 세부 정보


링크가 필요한 작업을 시도했는데 연결된 링크가 없으면 Workload Factory에서 알려줍니다. link:links-overview.html["링크에 대해 자세히 알아보세요"]을(를) 참조하십시오.

.링크를 사용하면 비용이 추가되나요?
네. 각 Lambda 트랜잭션에는 AWS 요금이 부과됩니다. Lambda는 프록시 역할을 하므로, 파일 시스템의 ONTAP REST API에 요청을 보낼 때와 Workload Factory로 응답을 다시 보낼 때 요금이 부과됩니다.

link:links-overview.html["링크에 대해 자세히 알아보세요"].

.파일 시스템이 둘 이상의 Link와 연결될 수 있습니까?
하나의 링크는 여러 FSx for ONTAP 파일 시스템과 연결될 수 있습니다. 각 파일 시스템은 동일한 NetApp 계정 내에서 하나의 링크에만 연결될 수 있습니다. 여러 NetApp 계정이 있는 경우, 파일 시스템은 다른 계정의 추가 링크와 연결될 수 있습니다. link:links-overview.html["링크에 대해 자세히 알아보세요"]를 참조하십시오.

.링크를 자동으로 생성해야 할까요, 아니면 수동으로 생성해야 할까요?
자동 생성은 Workload Factory를 통해 링크를 등록하지만, Workload Factory 자동화를 위해 토큰을 사용하며 해당 CloudFormation 코드는 최대 6시간 동안만 사용할 수 있습니다. 수동 생성은 Codebox에서 CloudFormation 또는 Terraform을 사용하며 코드가 유지됩니다. 이는 보안 및 DevOps 등 팀이 먼저 권한을 부여해야 할 때 유용합니다. GovCloud 계정은 링크를 수동으로 생성해야 합니다.

link:create-link.html["링크 생성"].

.링크를 만들기 전에 무엇이 준비되어 있어야 하나요?
파일 시스템의 보안 그룹에서 필요한 포트가 열려 있어야 하고, Link가  `\https://api.workloads.netapp.com`에 접근할 수 있어야 하며, CloudFormation 스택을 생성하기 위한 충분한 AWS 권한이 있어야 합니다.

link:create-link.html["Link를 생성하기 위한 전체 필수 조건 목록에 대해 알아보십시오."].

.링크의 인증 방식을 변경하거나, 링크를 생성한 후 수정할 수 있나요?
아니요. Link는 Workload Factory 자격 증명 또는 AWS Secrets Manager 중 하나의 인증 방법만 지원하며, 나중에 변경할 수 없습니다.

인터페이스에서는 링크를 편집할 수 없습니다. 링크를 변경하려면 새 링크를 생성하고 파일 시스템과 연결하십시오. AWS에서 Lambda 네트워크 구성을 변경하는 것은 연결 문제를 일으킬 수 있으므로 권장하지 않습니다.

link:manage-links.html["링크 관리"].

.링크를 삭제하면 어떻게 되나요?
해당 링크를 사용하던 파일 시스템 및 기타 리소스는 더 이상 링크에 의존하는 기능을 사용할 수 없습니다. 링크는 AWS가 아닌 Workload Factory에서만 삭제되므로 AWS 계정에서 Lambda 함수도 삭제해야 합니다.

link:manage-links.html["링크 삭제"].



[[codebox]]
== Codebox

.Codebox란 무엇이며 어떤 코드 형식을 생성합니까?
Codebox는 Workload Factory에서 지원하는 모든 작업을 실행하는 코드를 생성하는 IaC(Infrastructure as Code) 코파일럿입니다. Workload Factory REST API, AWS CLI, AWS CloudFormation 및 Terraform을 지원합니다. Codebox Viewer는 마법사 항목에서 생성된 코드를 보여주고, Automation Catalog는 저장된 작업을 재사용 가능한 템플릿으로 저장합니다.

link:codebox-automation.html["Codebox에 대해 자세히 알아보십시오"].

.Codebox에서 코드를 수정할 수 있나요? 생성된 코드는 만료되나요?
Codebox Viewer는 읽기 전용입니다. 코드를 복사하거나, Automation Catalog에 저장하거나, 일부 형식의 경우 다운로드만 가능합니다. 다운로드한 코드는 다른 AWS 계정에 맞게 편집할 수 있습니다. CloudFormation YAML 코드는 보안상의 이유로 7일 후 만료됩니다.

link:use-codebox.html["Codebox를 사용하십시오"].



[[cloudshell]]
== CloudShell

.CloudShell에서 무엇을 할 수 있으며, 제한 사항은 무엇입니까?
CloudShell은 사용자가 제공한 AWS 및 ONTAP 자격 증명을 사용하여 Workload Factory 백엔드를 통해 프록시되는 브라우저 기반 셸에서 AWS CLI 및 ONTAP CLI 명령을 실행합니다. 최소 하나 이상의 AWS 자격 증명이 필요합니다. 파이프 `|`, 백그라운드 `&` 및 리디렉션 `>` 등 셸 연산자는 지원되지 않으며, 이를 포함하는 명령은 실패합니다. AWS 명령은 선택한 자격 증명에 해당 리전에 대한 권한이 있는 경우에만 성공적으로 실행됩니다.

link:use-cloudshell.html["CloudShell을 사용합니다"].



[[notifications]]
== 알림

.Workload Factory는 어디로 알림을 보낼 수 있으며, 누가 알림을 관리하나요?
Workload Factory는 NetApp Console 알림, 계정과 연결된 이메일 주소로의 이메일, 또는 Amazon SNS 토픽으로 알림을 보낼 수 있습니다. 콘솔 알림은 콘솔 에이전트 또는 Link가 배포된 경우에 표시됩니다. NetApp Console에서 알림을 구성하면 콘솔에서 알림 전달을 담당하게 되며, Workload Factory 콘솔 알림 옵션은 읽기 전용으로 변경됩니다.

link:configure-notifications.html["알림을 구성합니다"].

.중요 알림을 위해 Amazon SNS를 사용하기 전에 무엇을 알아야 합니까?
Workload Factory는 표준 SNS 토픽 유형만 지원하며, 이 유형은 알림이 수신된 순서대로 구독자에게 전달된다는 보장이 없습니다. 중요 또는 긴급 알림의 경우 이 점을 고려해야 합니다. 구독자는 기본적으로 해당 토픽의 모든 알림을 수신하므로, 필요한 알림만 수신하려면 SNS 필터 정책(리소스 유형, 워크로드, 우선순위 또는 알림 유형별)을 사용하십시오.

link:configure-notifications.html["알림을 구성합니다"].



[[service-accounts]]
== 서비스 계정

.서비스 계정은 언제 사용해야 하며, 계정의 비밀 키에 대해 무엇을 알아야 할까요?
API 전용 자동화에는 서비스 계정을 사용하여 스크립트가 개인의 사용자 계정에 종속되지 않도록 하십시오. 클라이언트 시크릿은 한 번만 표시되며 Workload Factory에 저장되지 않으므로 서비스 계정을 생성할 때 복사하거나 다운로드하십시오. 클라이언트 ID와 시크릿으로 생성된 액세스 토큰은 수명이 짧아 몇 시간 동안만 유효합니다. Workload Factory 콘솔에서는 서비스 계정을 생성하거나 삭제할 수만 있습니다. 새 시크릿을 얻으려면 서비스 계정을 삭제하고 새 계정을 생성하십시오.

link:manage-service-accounts.html["서비스 계정을 관리합니다"].



[[well-architected-analysis]]
== 잘 설계된 분석

.잘 설계된 분석은 어떻게 작동하며, Link가 필요한가요?
Workload Factory는 매일 FSx for ONTAP 파일 시스템을 검사합니다. 구성을 최적화됨 또는 최적화되지 않음으로 평가하고, 권장 사항을 제공하며, 일부 문제는 자동으로 해결할 수 있지만 다른 문제는 수동 단계가 필요합니다. 환경에 적용되지 않는 검사를 무시하거나 일반 언어로 사용자 지정 규칙을 생성할 수 있습니다. 파일 시스템에 대한 포괄적인 분석을 위해서는 Link를 생성하여 파일 시스템과 연결해야 합니다.

link:well-architected-workloads.html["잘 설계된 분석에 대해 자세히 알아보세요"].



[[tracker]]
== 트래커

.Tracker란 무엇이며, 작업 이력은 얼마나 오래 보관하고, 실패한 작업은 어떻게 처리할 수 있습니까?
Tracker는 Workload Factory의 모니터링 툴이며 사용자 인터페이스에 30일 동안 이벤트를 보관합니다. 기간, 워크로드, 상태 및 사용자별로 필터링할 수 있으며 작업 테이블을 CSV 파일로 다운로드할 수 있습니다. 실패한 작업의 경우 다시 시도하거나 매개변수를 수정하여 다시 시도할 수 있습니다. 실패한 작업에 허용되는 재시도 횟수는 제한되어 있습니다.

link:monitor-operations.html["Tracker를 사용하여 운영 상황을 모니터링하세요"].



[[ai-features]]
== AI 기능

.AI 기능은 어떻게 제어하며, 기능을 끄면 어떻게 되나요?
AI 설정 페이지에서 관리자는 NetApp 관리형 Bedrock(권장)을 선택하거나 모든 AI 기능을 끌 수 있습니다. NetApp 관리형 Bedrock은 모델 학습에 사용자 데이터를 사용하지 않으며 추가 AWS 설정이 필요하지 않습니다. AI 기능을 끄면 Ask Me, AI 에이전트, 사용자 지정 대시보드, 규칙 빌더, 분석기 및 CloudShell의 AI 오류 응답을 사용할 수 없게 됩니다. AI 기능은 공용 AWS 리전의 AWS Bedrock을 사용하므로 GovCloud 계정에는 이 점이 중요할 수 있습니다.

link:manage-genai-features.html["AI 기능 관리"].

.AI 사용에 제한이 있습니까?
예. NetApp에서 관리하는 Bedrock의 경우, 각 계정에는 각 AI 기능에 대한 월별 지출 한도가 있습니다. 이 한도에 도달하면 Workload Factory는 AI 기능을 비활성화하고 인터페이스의 관련 부분을 회색으로 표시하며 툴팁을 표시합니다. 크레딧을 더 받으려면 NetApp 담당자에게 문의하십시오.

.AI 에이전트가 AWS 또는 ONTAP 리소스를 변경할 수 있습니까?
기본적으로 에이전트는 읽기 전용 모드로 실행되며 리소스를 변경할 수 없습니다. 선택 사항인 읽기/쓰기 모드에서는 에이전트가 각 작업을 요약하고 사용자가 승인한 후에만 선택한 자격 증명을 사용하여 작업을 수행합니다. 에이전트는 현재 범위 내의 리소스와 에이전트 설정에서 선택한 자격 증명에만 액세스할 수 있으며, 자격 증명을 선택한다고 해서 추가적인 AWS 권한이 부여되는 것은 아닙니다.

* link:learn-agent.html["AI 에이전트에 대해 알아보기"].
* link:manage-agent-settings.html["에이전트 설정 관리"].




[[custom-dashboards]]
== 맞춤형 대시보드

.사용자 지정 대시보드를 보거나 편집하거나 삭제할 수 있는 사람은 누구입니까?
새 대시보드는 생성자만 볼 수 있습니다. 공유하면 Workload Factory 계정의 모든 사용자에게 대시보드가 공개되며, 계정 외부로는 공유할 수 없습니다. 생성자만 대시보드를 편집할 수 있지만, 계정의 모든 사용자는 대시보드를 삭제할 수 있습니다. 삭제는 영구적이며 모든 사용자에게서 대시보드가 제거되므로 팀과 조율하십시오.

* link:learn-custom-dashboards.html["맞춤형 대시보드에 대해 알아보기"].
* link:manage-custom-dashboards.html["사용자 지정 대시보드 관리"].


.사용자 지정 대시보드를 만들고 사용하려면 무엇이 필요합니까?
계정 관리자가 AI 기능을 활성화해야 합니다. 모니터링하려는 서비스에 대한 읽기 권한이 있는 AWS 자격 증명이 필요합니다. FSx for ONTAP 파일 시스템에 연결하려면 Link가 필요합니다. 대시보드는 읽기 전용이며 스토리지 또는 워크로드 설정을 변경할 수 없습니다.

link:learn-custom-dashboards.html["맞춤형 대시보드에 대해 알아보기"].
