= NetApp Workload Factory 링크 관리
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Workload Factory 계정에 연결된 링크를 관리할 수 있습니다. FSx for ONTAP 파일 시스템과 연결된 링크를 확인하고, 링크 인증에 사용되는 암호를 제공하고, Workload Factory 콘솔에서 링크를 제거할 수 있습니다.

link:links-overview.html["링크에 대해 자세히 알아보기"] 또는 link:create-link.html["링크를 생성하고 연결합니다"].



[[view-the-links-associated-with-your-account]]
== 계정과 연결된 링크를 확인합니다

현재 계정에 연결된 링크를 확인할 수 있습니다.

.단계
. 다음 중 하나를 사용하여 로그인하세요link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["콘솔 환경"^].
. 저장소 메뉴에서 *관리*를 선택한 다음 *링크*를 선택합니다.
+
기존 링크는 링크 페이지에 표시됩니다.

. 링크와 연결된 FSx for ONTAP 파일 시스템을 보려면 연결된 리소스 섹션에서 *보기* 버튼을 선택하십시오.
+
image:screenshot-view-link-details.png["특정 링크를 사용하는 FSx for ONTAP 파일 시스템을 보여주는 스크린샷."]

. 링크에 사용할 Amazon Resource Name(ARN)이 필요한 경우 ARN 필드 옆에 있는 _복사_ 아이콘을 선택하면 됩니다.




[[edit-a-link]]
== 링크 수정

Workload Factory 인터페이스에서는 링크를 편집할 수 없습니다. 링크를 변경해야 하는 경우 새 링크를 생성한 다음 해당 링크를 파일 시스템에 연결해야 합니다.


NOTE: AWS 콘솔을 사용하여 Lambda 네트워크 구성(예: VPC, 서브넷 및 보안 그룹)을 편집할 수 있으며 변경 사항은 링크 관리 UI에 반영됩니다. 그러나 이러한 변경은 Lambda와 ONTAP 간의 연결 문제를 일으킬 수 있으므로 권장하지 않습니다.



[[authenticate-a-link]]
== 링크 인증

FSx for ONTAP 파일 시스템에 링크를 연결하려면 Workload Factory 자격 증명에 대한 관리자 사용자 암호 또는 AWS Secrets Manager 비밀 ARN을 제공하십시오.

콘솔 에이전트를 사용할 때는 AWS Secrets Manager가 지원되지 않습니다.


NOTE: 링크당 하나의 인증 방법만 지원됩니다. 예를 들어 AWS Secrets Manager를 사용한 링크 인증을 선택한 경우 나중에 인증 방법을 변경할 수 없습니다.

.단계
. 다음 중 하나를 사용하여 로그인하세요link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["콘솔 환경"^].
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 스토리지, EDA, AI, 데이터베이스, VMware 및 관리와 같은 워크로드를 탐색하는 데 사용됩니다."]를 선택한 다음 *Storage*를 선택합니다.
. Storage 메뉴에서 *FSx for ONTAP*를 선택합니다.
. *FSx for ONTAP*에서 링크를 연결할 파일 시스템의 작업 메뉴를 선택한 다음 *관리*를 선택합니다.
. 파일 시스템 개요에서 *링크 인증*을 선택합니다.
. 인증 링크 페이지에서 인증 모드를 선택합니다.
+
** Workload Factory: 비밀번호를 두 번 입력합니다.
** AWS Secrets Manager: 비밀 ARN을 입력하십시오.


. Apply * 를 선택합니다.


.결과
링크가 인증되었으므로 고급 ONTAP 작업을 수행할 수 있습니다.



[[update-the-password-for-link-authentication]]
== 링크 인증 비밀번호 업데이트

관리자 암호가 유효하지 않은 경우, 암호를 업데이트하여 FSx for ONTAP 파일 시스템에 대한 링크를 연결하십시오.

.단계
. 다음 중 하나를 사용하여 로그인하세요link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["콘솔 환경"^].
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 스토리지, EDA, AI, 데이터베이스, VMware 및 관리와 같은 워크로드를 탐색하는 데 사용됩니다."]를 선택한 다음 *Storage*를 선택합니다.
. Storage 메뉴에서 *FSx for ONTAP*를 선택합니다.
. *FSx for ONTAP*에서 링크를 연결할 파일 시스템의 작업 메뉴를 선택한 다음 *관리*를 선택합니다.
. 파일 시스템 개요에서 *암호 업데이트*를 선택합니다.
. 인증 링크 페이지에서 새 비밀번호를 두 번 입력합니다.
. Apply * 를 선택합니다.


.결과
암호가 업데이트되었으며, 이제 링크가 FSx for ONTAP 파일 시스템에 연결되었습니다.



[[remove-a-link]]
== 링크 제거

환경에서 더 이상 사용하지 않는 링크를 제거할 수 있습니다. 링크를 제거하면 해당 링크를 사용하던 FSx for ONTAP 파일 시스템 또는 기타 리소스에서 특정 기능을 사용할 수 없게 됩니다.

링크는 Workload Factory에서만 삭제되며 AWS 환경에서는 삭제되지 않습니다. Workload Factory에서 링크를 제거한 후에는 AWS 계정에서 Lambda 함수를 삭제해야 합니다.

.단계
. 다음 중 하나를 사용하여 로그인하세요link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["콘솔 환경"^].
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 스토리지, EDA, AI, 데이터베이스, VMware 및 관리와 같은 워크로드를 탐색하는 데 사용됩니다."]를 선택한 다음 *Storage*를 선택합니다.
. 저장소 메뉴에서 *관리*를 선택한 다음 *링크*를 선택합니다.
+
기존 링크는 링크 페이지에 표시됩니다.

. 링크 페이지에서 삭제할 링크의 작업 메뉴를 선택한 다음 *Remove*를 선택합니다.
+
image:screenshot-remove-link.png["Workload Factory에서 링크를 제거하는 방법을 보여주는 스크린샷입니다."]

. 확실하다면 *제거*를 다시 선택하십시오.


자세한 내용은 AWS 설명서를 참조하십시오link:https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-awscli.html#with-userapp-walkthrough-custom-events-delete-function["Lambda 함수를 삭제합니다"].
